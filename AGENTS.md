# AGENTS.md — заметки для будущих сессий

## Что это

«Живое существо» — цифровой ребёнок в Minecraft. Два независимых процесса:

- **Тело** — `bot.js` (Node.js + mineflayer). Подключается к серверу Minecraft
  и отдаёт HTTP API на `localhost:3000`: сенсоры (`/state`, `/self`, `/vision`,
  `/sounds`, `/world`, `/messages`, `/player_actions`) и моторика (`POST /action`).
- **Мозг** — Python-пакет `core/`, запускается через `run.py`. Ничего не знает
  про mineflayer: видит только адаптер (`adapters/`).

Связь односторонняя через адаптер: мозг опрашивает сенсоры и шлёт действия.

## Как запускать

```bash
# зависимости мозга
pip install -r requirements.txt

# терминал 1: тело (нужен Minecraft-сервер, хост/порт в начале bot.js)
node bot.js

# терминал 2: мозг
python run.py

# мозг без Minecraft (искусственное тело, для разработки/тестов)
python run.py --mock
python run.py --mock --steps=100   # с лимитом шагов
```

LLM (`Ollama`, модель `qwen2.5:3b`) необязательна. Без неё мозг работает:
внутренний голос переключается на шаблоны из внутреннего состояния, а команды
распознаются по словам-подсказкам (`core/adaptive_intent.py`, `HINTS`).

## Архитектура (важно не путать слои)


## Ключевые инварианты

- **Драйвы — центр всего.** Напряжение (`Drives.tension()`) запускает поведение.
  `comfort` — производная величина, её нельзя включать в `dominant()`.
- **Предсказание = два механизма.** `NeuralColumn` обобщает, но «мажет»
  (обучается на один шаг и размывает сигнал между действиями). Быстрая
  `relief_table` (JSON) надёжно помнит пары action→drive. `simulate()`
  смешивает их (75% таблица, 25% колонна, когда есть прямой опыт).
  `DRIVE_WEIGHTS['comfort'] = 0` — comfort исключён из оценки напряжения.
- **API адаптера** — единственный контракт между мозгом и телом:
  `get_state / get_self / get_vision / get_sounds / get_world / get_messages /
  get_player_actions / get_actions / get_tasks / get_game / clear_messages /
  action / say`. `actions.py`, `self_model.py`, `world_model.py` работают через
  него, а не напрямую через HTTP — иначе mock-тело не заработает.
- **Задачи игры — не то же, что учебная программа.** `TaskTracker`
  (`core/tasks.py`) спрашивает у тела `get_tasks()`: чего хочет сама игра
  (достижения/квесты). Это имеет приоритет над своим планом роста, но
  подчиняется драйвам: голод и опасность важнее любой задачи.
- **Понятия — из признаков, а не из имён.** `core/concepts.py` выводит законы
  (гравитация, опора, проход, соединение, ...) из `extract_features()`
  (есть ли опора, сдвинулся ли, открылось ли), поэтому они переносятся в любую
  игру. `Cortex.choose_action` учитывает `ConceptLearner.advice()`: закон
  может запретить действие (`forbid`) или поднять его ценность.
- **Материалы одного рода взаимозаменяемы.** `core/recipes.py` (`count_in`,
  `material_family`, `has_tool`) считает любое дерево деревом (`birch_log`
  закрывает нужду в `oak_log`), а инструмент — по порядочности (железная кирка
  вместо деревянной). Тела (`bot.js`, `adapters/mock.py`) при крафте сами
  подбирают подходящую породу, потому что рецепт Minecraft привязан к породе.
  Это правило универсально: в другой игре — свои породы, смысл тот же.
- **Успех проверяется по миру, а не по слову тела.** `CraftingSkill._no_progress`
  после действия берёт СВЕЖИЙ инвентарь (`sense`) и, если вещь не появилась,
  объявляет причину `no_progress` и ищет другой путь. Иначе существо, которому
  тело отвечает «добыл», а блок не тот (или его нет рядом), копает вечно.
- **Неудача → причина → средство.** `core/causality.py` (`Reasoner`) разбирает
  каждую неудачу: тело сообщает `reason` (`no_tool`, `locked`, `out_of_reach`),
  либо причина выводится из признаков мира (`blocked` → «стена», нет
  `support_below` → «нет опоры»). Причина превращается в связь «не хватает X →
  делаю Y», запоминается в `beliefs` (`data/causes.json`) и влияет на поведение:
  `Reasoner.advice()` поднимает ценность средства или запрещает вредное
  (копать вниз без опоры). `CraftingSkill._try_remedy()` пробует средство до
  того, как сдаться. Причина опирается на смысл, а не на имя блока, поэтому
  переносится между играми.
- **Все моторные команды идут через `cortex.act()`**, чтобы обучение
  (сравнение ожидания и реальности) охватывало каждое действие.
  `CraftingSkill` получает `cortex.act` как функцию `act` — ремесло не в обход.
- **Человеческое ядро не отменяет нужды, а окрашивает их.** Порядок решения в
  `_autonomous_step`: сначала уклонение от угрозы/ямы (выживание), затем
  метапознание (`_meta_step`: залип — сменить подход), затем планы и ремесло,
  затем в свободную минуту — утешение/вопрос/игра/привычка (`_play_and_habits`).
  Регуляция чувства (`_regulate`) запускается ТОЛЬКО без дела и вне опасности,
  иначе она крадёт шаги у работы.
- **Эмоция — из оценки, а не из реакции.** `Emotions.appraise(event)` получает
  смысл события (`harm`, `benefit`, `novelty`, `control`, `self_agency`, `norm`,
  `loss`, `blocked`, `attachment`) и выводит чувство. Порядок правил важен:
  сильные/негативные чувства (стыд, страх, боль, печаль) перекрывают слабые
  (любовь, радость) — иначе существо «радуется» с киркой в спине.
- **Настроение медленное, эмоция инертна.** Новое чувство переживается, только
  если оно сильнее текущего (`> current.intensity + 0.05`); привязанность
  чувствуется волнами (`random.random() < 0.12` за шаг), а не каждый тик.
  Так эмоция не дёргается и не засоряет эмоциональную память.
- **Привычка ломается без результата.** `Habits.punish()` ослабляет привычку
  при неудаче; `Habits.IDLE` (смотреть/ждать) привычкой не становятся вообще —
  иначе существо застывает. Привычка помогает, но не залипает.
- **Разлука измеряется шагами, а не часами.** `Social.update` считает
  `away_ticks`, а не wall-clock, — существо живёт шагами мозга, а в тестах и
  быстрых прогонах время почти не идёт.
- **Возраст — от опыта, а не от времени.** `Development.live()` растёт от
  прожитых шагов (новизна ускоряет). От стадии зависят длина фразы
  (`Language.phrase`), сила игры, любопытства, терпения.
- **Человеческие системы сохраняются** в `_consolidate()` и периодически в
  `run.py` (feelings, social, habits, meta, language, development, temperament,
  play) — состояние в `data/*.json` переживает перезапуск.
- **Ремесло — это прогрессия, а не список.** `Recipes` знает зависимости,
  `Curriculum` — порядок ступеней (дерево → верстак → кирка → камень → печь →
  железо → броня → кровать), `CraftingSkill` перед каждым шагом пересчитывает,
  чего не хватает, и делает ровно одно действие. Плавка (`iron_ingot`) — это
  `kind: 'smelt'`, а не `craft`: в теле это `bot.openFurnace`, не `bot.craft`.

## Тесты

Проверки лежат в `tests/` и запускаются без Minecraft:

```bash
make test          # компиляция + все тесты
python tests/run_all.py
```

- `tests/test_brain.py` — колонна (разреженность, обучение, save/load),
  предиктор (`eat_food→hunger`), внимание (побеждает угроза), ёмкость рабочей
  памяти (≤7), эпизоды, драйвы, планировщик.
- `tests/test_survival.py` — выход из ямы, уход из чёрной клетки,
  самоокапывание, анти-повтор.
- `tests/test_speech.py` — команды, приветствия, разговор, имитация,
  плейсхолдеры LLM, ограничение истории целей, дубли нарратива.
- `tests/test_crafting.py` — разложение цели на сырьё, топологический порядок
  (дерево → доски → палки → верстак → кирка), сквозная цепочка до железа,
  прохождение всех 28 ступеней программы на mock-теле.
- `tests/test_concepts.py` — вывод законов (гравитация, опора, стена, проход,
  соединение, опасность, питание, инструмент), совет поведению, безопасный
  опыт, выбор и выполнение задач игры (рецепт и задача-действие).
- `tests/test_causality.py` — разбор причин неудач (из `reason` тела и из
  признаков мира), память причин с сохранением, средство против причины,
  подсказка поведению, размышление вслух и перенос причины в другую игру.
- `tests/test_mind.py` — человеческое ядро: характер рождается и сохраняется,
  интероцепция, эмоция из ОЦЕНКИ (страх перекрывает любовь, стыд, печаль),
  регуляция снижает накал, привязанность/разлука/встреча, игра от настроения,
  привычка закрепляется и ЛОМАЕТСЯ, метапознание ловит залипание, речь растёт
  по возрасту, взросление от опыта, сквозной прогон живого мозга.
- `tests/test_games.py` — универсальность: один и тот же мозг проходит
  Minecraft-песочницу и второе подземелье (`adapters/game2.py`) без правок под
  игру; понятия переносятся между играми. Тест изолирует `data/` и фиксирует
  зёрна, поэтому не зависит от порядка запуска.

`tests/_env.py` переключает рабочую папку в свежий временный каталог, поэтому
тесты не трогают `data/` в репозитории.

## Данные

Всё состояние живёт в `data/` (JSON + `neural_predictor.npz`) и переживает
перезапуск: память, нейромодуляторы, выученные фразы, эпизоды, веса колонны.

## Известные ограничения

- Требуется реальный сервер Minecraft для настоящего тела; хост/порт
  захардкожены в `bot.js` (начало файла) — при необходимости правьте там.
- `pyttsx3` в контейнере обычно без аудио — голос тихо выключается.
- Ollama недоступен в CI — не полагайтесь на LLM в тестах.
